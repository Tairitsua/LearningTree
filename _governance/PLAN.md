# LearningTree 知识库治理计划

> 治理工作区：本目录（`_governance/`）存放治理期间的中间产物（计划、盘点、事实验证记录、迁移日志、报告）。
> 治理完成后保留作为审计记录。仓库本体 = Obsidian vault，规范见根 `AGENTS.md`（治理产出）。

## 目标

1. 知识结构体系分析：整理、分类知识，调整文件夹架构（保留全部信息，只动组织方式）。
2. 格式治理：按用户既有格式规范（原 README 底部 AI 提示词）修复格式问题。
3. 事实治理：对可疑事实做权威来源查证，修正错误并留痕。
4. 建立长效机制：根 `AGENTS.md` + 知识入库技能（skill），支撑"扔进一条知识点 → agent 自动归位"的工作流。

## 硬约束

- **不丢信息**：只重组、修格式、修错；内容删减必须留痕于 `_governance/`。
- **链接完整性**：Obsidian 配置为标准 Markdown 相对链接（`useMarkdownLinks: true` / `newLinkFormat: relative`）。移动/改名文件后必须改写引用它的与它引用的相对链接（含 `%20` URL 编码）。治理收尾必须跑链接校验脚本，0 死链。
- **图片**：全部平铺于根 `attachments/`，移动笔记时重算相对前缀；孤儿图片隔离到 `attachments/_orphan/` 留档不删除。
- **git**：阶段性 commit（无需用户检查），每次 commit 前跑链接校验。

| F 验收收尾 | 链接/孤儿/标题结构校验、README 重写、总报告 | `REPORT.md` |

## 用户既有格式规范（原 README，治理时遵循）

1. 文件标题作为 H1，文件内部不再出现其他 H1。
2. 专有英文名词用反引号包裹。
3. 代码必须用带语言标注的代码块；行内代码/命令用反引号。
4. 尽量不改动内容本身，仅修复格式、语法或事实错误；事实修正必须总结。
5. 标号统一为 Markdown 列表序号（①等需替换）。
6. 裸外链 `<https://...>` 替换为 `[标题](URL)` 可读格式。
7. 大段英文原文不翻译，仅调格式。
8. 超大文件按章节（H1→H2 递归）拆分为同名文件夹下的小文件。
